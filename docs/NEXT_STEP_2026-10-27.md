# What next? (27 October 2026)

## Immediate gate: make the evaluation non-trivial

The existing Annex 3a case has TWO clauses and 4 independently authored question groups / 12 script variants. For queries after time filtering, the answer can become a **single remaining candidate**. This checks the date filter but DOES NOT establish that the retrieval algorithm truly understands time or script.

Do not report an impressive top-1 percentage from this demo as an academic result.

## Next research steps
1. Verify at least five further older/newer clause pairs from other document families, with **hard negatives** (semantically similar passages from the wrong date). Human-verify the original legal editions.
2. Create at least 20 independently worded base questions for a clearly labeled exploratory pilot, with three script variants per question and a log of annotator confirmation. These are **provisional targets**, not a substitute for adequate statistical power.
3. Keep both question families and document families separate across development/test evaluation. Do not count translated/transliterated variants as independent observations.
4. Run five baselines and error analysis, freeze experiment settings, report uncertainty and failures. Use `python -m scripttime evaluate --case annex3a` strictly as an engineering smoke test.
5. Only then draft a narrow conference report based on true findings. A larger (30+ clauses, 60+ independent groups) study and model fine-tuning can continue after the submission deadline.
